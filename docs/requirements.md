## Требования к проекту

### User Stories

| ID | User Story |
|----|------------|
| US-001 | Как **Пользователь**, я хочу получать список рекомендаций продуктов по своему ID, чтобы видеть подходящие предложения. |
| US-002 | Как **Менеджер**, я хочу создавать, читать и удалять динамические правила через API, чтобы управлять бизнес-логикой без перезапуска приложения. |
| US-003 | Как **Внешняя система** (мониторинг), я хочу сбрасывать кэш статистики пользователей и получать метрики приложения, чтобы поддерживать актуальность данных и контролировать нагрузку. |

### Non-Functional Requirements

| ID | Требование |
|----|------------|
| NFR-001 | Производительность: среднее время ответа эндпоинта `/recommendation/{user_id}` не должно превышать 200 мс при нагрузке до 100 RPS. |
| NFR-002 | Логирование: все ошибки бизнес-логики и исключения БД должны логироваться с уровнем ERROR и содержать контекст (user_id, rule_id). |
| NFR-003 | Надежность: приложение должно корректно обрабатывать отсутствие правил в БД (возвращать пустой список, а не 500). |

## Диаграмма вариантов использования (Use Case)

actor "Пользователь" as User
actor "Менеджер" as Manager
actor "Внешняя система" as External

  usecase "/recommendation/{user_id}" as UC1
  usecase "/rule (POST/GET/DELETE)" as UC2
  usecase "/management/cache/reset" as UC3
  usecase "Сбор метрик" as UC4
}
